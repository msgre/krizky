# 2026-07-16-01 — Parameterized query runner (`queries:` config section)

## Co bylo implementováno

### Nová config sekce `queries:` (top-level)

```yaml
queries:
  nearby:
    sql: |
      SELECT *,
        ROUND(6371000 * acos(
          cos(radians({{ latitude }})) * cos(radians(latitude)) *
          cos(radians(longitude) - radians({{ longitude }})) +
          sin(radians({{ latitude }})) * sin(radians(latitude))
        )) AS distance_m
      FROM [mista]
      WHERE distance_m < {{ radius|default(500) }}
      ORDER BY distance_m
      LIMIT {{ limit|default(10) }}
    parameters:
      - latitude
      - longitude
```

SQL šablona používá Jinja2 syntaxi. Parametry jsou předány při volání `query(name, **params)` v šabloně.

### Funkce `query()` v Jinja2 kontextu

Dostupná ve všech šablonách (stejně jako `tables`, `docs`, `build`, `site`):

```jinja2
{% set nearby = query('nearby', latitude=record.latitude, longitude=record.longitude) %}
{% for place in nearby %}
  <a href="{{ place.slug }}.html">{{ place.nazev }}</a> — {{ place.distance_m }} m
{% endfor %}
```

### Bezpečnost — parameterized SQLite queries

Klíčový detail: parametry (`{{ latitude }}` apod.) se NEinterpolují přímo do SQL stringu. Místo toho jsou nahrazeny `?` placeholders a hodnoty předány SQLite nativně.

Mechanismus (`_SqlProxy` trick):
1. Každý parametr je obalený do `_SqlProxy(value, collector)`
2. Jinja2 renderuje SQL template — když zapíše `{{ latitude }}`, zavolá `str(proxy)`, který:
   - vrátí `"?"` do výsledného SQL stringu
   - uloží skutečnou hodnotu do `collector.values`
3. Výsledek: `(sql_with_placeholders, [val1, val2, ...])` → `conn.execute(sql, values)`

Výsledek: SQL injection útok přes hodnotu v DB je nemožný:
```
"'; DROP TABLE mista; --"  →  WHERE name = ?  (hodnota je binding, ne součást SQL)
```

Konstanty z configu (`{{ limit|default(10) }}` kde `limit` není v params) se renderují jako literály — bezpečné, protože pocházejí z developer-controlled config souboru.

### Caching

`QueryRunner` cachuje výsledky per `(name, tuple(sorted(params.items())))`. Druhé volání `query('nearby', latitude=X, longitude=Y)` se stejnými hodnotami vrátí stejný list objekt bez nového DB dotazu. Kritické pro detail stránky, kde by se stejná query volala vícekrát (různé include soubory atd.).

### Error handling

- Neznámý name query → `log.warning`, vrátí `[]` (nevyhodí výjimku — nerozbije build)
- Chybné SQL → `log.error`, vrátí `[]`
- Unhashable parametry → přeskočí cache, stále vykoná query

## Technické poznámky

- Omezení: aritmetika v Jinja2 template (`{{ latitude + 0.01 }}`) není podporována — proxy nepodporuje `__add__` atd. Matematiku je třeba psát v SQL (SQLite funkce jako `radians()` apod. fungují správně).
- `_sql_env` je samostatný Jinja2 Environment bez md/mdtext filtrů — SQL je jiný kontext než HTML.
- Klíč `parameters:` v config sekci je zatím dokumentační — validace, zda byly předány správné parametry, není implementována (chybějící parametry tichně propadnou přes `|default` nebo způsobí SQL chybu, která se zaloguje).
